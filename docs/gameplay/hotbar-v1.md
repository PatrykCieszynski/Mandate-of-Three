# Hotbar V1 — foundational bindings

This PR introduces only **eight quick-slot bindings**. Slots point to an item UID or a skill ID, never own item instances or skill state. Missing inventory items and unlearned skills resolve to an unusable binding. The CEF page renders an empty, noninteractive bar. Connecting these bindings to its presentation, activation and saved preferences remains deferred.

The current horn PR (#54) still exposes its provisional H key, default/basic tier, and server cooldown. Before integrating with the hotbar, implement an authoritative item USE path checking equipped/owned horn UID and tier on each invocation. Never trust a client's claimed tier, inventory slot or cooldown. Do not ship a hotbar that calls a free/unowned horn skill as an item shortcut.

Also deferred: drag/drop UX, action feedback and cooldown overlays, HP/MP projection and layout, binding save/load via account settings and reconnect, keyboard focus rules.

The bar is composed in the existing CEF page; it adds no native Godot HUD or CoreUiController gameplay responsibility.

## Bottom CEF preview

The same PR now mounts a persistent bottom-center 8-slot bar in the existing `web/inventory/game.html` CEF page. Its CSS uses the shared `--skin-slot-normal`, `--frame`, `--ink`, and `--muted` values already used by the Metin-inspired inventory skin. The bar is deliberately pointer-transparent and displays empty reference slots, because actual item UID activation, assignment, skill activation and cooldown sync have not yet been wired. It contains no hardcoded health/mana figures.

Before enabling interactions, integrate slot binding state through existing `UiCommandDispatcher` domains and validate item USE authorization on the server. Keep the CEF pointer-region lease accurate once the bar becomes interactive.

## Build and scale

`ts/inventory/bottom-hud.ts` owns the component; `ts/inventory/game.ts` mounts it,
applies the same validated `ui_scale` used by the window manager on initial
snapshots and HUD updates, and disposes it on page unload. Files under `web/`
are generated by the existing TypeScript build, not edited as independent code.

The HUD stays anchored at bottom-center with a bottom-center scale origin.
`--hotbar-slot-size` defaults to 40 logical pixels; slots do not shrink with
viewport width. The supported viewport/scale matrix fits without a fluid layout.
The passive bar adds no CEF interactive region or keyboard handler.

Verification uses the existing binding smoke test and browser preview case:
initial mount, a HUD scale update, pointer transparency, persistence when windows
close, and UI reload. These checks do not validate native CEF input or final art.
